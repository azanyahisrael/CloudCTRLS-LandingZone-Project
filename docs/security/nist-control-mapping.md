# NIST SP 800-53 Control Mapping

Controls are listed only once something in the repository supports them. Status is **Partial** until enforcement is automated and tested.

| Control | Name | How CloudCTRLS supports it | Status | Evidence |
|---|---|---|---|---|
| AC-2 | Account Management | AWS human access is managed centrally in IAM Identity Center: one directory user, permission sets assigned per account in Terraform, short-lived sessions instead of IAM user access keys. | Partial | [Phase 3, Step 4](../implementation/phase-3-landing-zones.md#step-4-aws-organization-scps-and-iam-identity-center), [ADR-0009](../decisions/0009-aws-organization-and-identity.md) |
| IA-5(7) | No Embedded Unencrypted Static Authenticators | `.gitignore` excludes `.env` files, keys, certificates, `*.tfvars` and Terraform state so credentials are not committed. Storage account keys are disabled on the state backend, so no shared secret exists for it. Automated secret scanning (Gitleaks) is planned for Phase 7. | Partial | [Phase 1, Step 2](../implementation/phase-1-foundation.md#step-2-repository-safety-files) |
| IA-2(1) | Multi-Factor Authentication to Privileged Accounts | MFA on the AWS root user and the Azure administrator account. AWS human access goes through IAM Identity Center with MFA required at every sign-in. | Partial | [Phase 2, Step 2](../implementation/phase-2-terraform-foundation.md#step-2-account-safety-before-billable-resources), [Phase 3, Step 4](../implementation/phase-3-landing-zones.md#step-4-aws-organization-scps-and-iam-identity-center) |
| SC-28 | Protection of Information at Rest | Terraform state (which can contain secrets) is encrypted at rest: Azure Storage infrastructure (double) encryption; S3 SSE-S3 (AES-256), moving to a customer-managed KMS key in Phase 3. | Partial | [Step 4a](../implementation/phase-2-terraform-foundation.md#step-4a-azure-state-backend), [Step 4b](../implementation/phase-2-terraform-foundation.md#step-4b-aws-state-backend) |
| SC-8 | Transmission Confidentiality and Integrity | State backends require encrypted transport: Azure Storage enforces HTTPS with TLS 1.2 minimum; the S3 bucket policy denies any non-HTTPS request. | Partial | [Step 4a](../implementation/phase-2-terraform-foundation.md#step-4a-azure-state-backend), [Step 4b](../implementation/phase-2-terraform-foundation.md#step-4b-aws-state-backend) |
| CM-2 | Baseline Configuration | The Azure policy baseline is defined in Terraform and assigned on `mg-cloudctrls`, so every CloudCTRLS environment inherits the same guardrails. AWS SCPs are defined in Terraform and attached to `ou-cloudctrls` the same way; changes go through code and `terraform plan`. | Partial | [Phase 3, Step 2c](../implementation/phase-3-landing-zones.md#step-2c-azure-policy-baseline), [ADR-0008](../decisions/0008-azure-policy-baseline.md), [ADR-0009](../decisions/0009-aws-organization-and-identity.md) |
| CM-6 | Configuration Settings | Azure Policy denies resources outside `eastus` and resource groups missing required tags. AWS SCPs deny actions outside `us-west-2` and `us-east-1` and disabling CloudTrail, Config or GuardDuty; both AWS denials were tested. The Azure denial test is pending. | Partial | [Phase 3, Step 2c](../implementation/phase-3-landing-zones.md#step-2c-azure-policy-baseline), [Phase 3, Step 4](../implementation/phase-3-landing-zones.md#step-4-aws-organization-scps-and-iam-identity-center) |
| CM-8 | System Component Inventory | Every resource, and the `sub-cloudctrls-prod` subscription, carries the standard tags (`project`, `env`, `cloud`, `region`, `purpose`, `managed_by`) from the tested naming module, so inventory can be queried by tag. Azure Policy denies resource groups missing `project`, `env` or `managed_by`. | Partial | [Phase 3, Step 2a](../implementation/phase-3-landing-zones.md#step-2a-management-group-hierarchy-and-dedicated-subscription), [Step 2c](../implementation/phase-3-landing-zones.md#step-2c-azure-policy-baseline) |
| AU-2 | Event Logging | Logged events in Azure are defined in code: all subscription activity log categories, and read, write and delete on the Terraform state storage. AWS logging (CloudTrail) follows in Step 3.5. | Partial | [Phase 3, Step 3](../implementation/phase-3-landing-zones.md#step-3-azure-central-logging) |
| AU-11 | Audit Record Retention | The central Log Analytics workspace keeps logs 30 days. Long-term archive is not yet configured. | Partial | [Phase 3, Step 3](../implementation/phase-3-landing-zones.md#step-3-azure-central-logging) |
| AU-12 | Audit Record Generation | Diagnostic settings managed by Terraform send audit records to one workspace; arrival verified by query. A daily ingestion cap can drop records once reached. | Partial | [Phase 3, Step 3](../implementation/phase-3-landing-zones.md#step-3-azure-central-logging) |
| CP-9 | System Backup | State versioning in both clouds (Azure 30-day soft delete, S3 noncurrent versions kept 30 days) allows recovery from corruption or deletion; a `CanNotDelete` lock and `prevent_destroy` protect the backends. | Partial | [Step 4a](../implementation/phase-2-terraform-foundation.md#step-4a-azure-state-backend), [Step 4b](../implementation/phase-2-terraform-foundation.md#step-4b-aws-state-backend) |
